# Sprite streaming and fast-scroll performance analysis

Date: 2026-10-25. Baseline: `56dc550c` (0.63.0). Scope: analysis and implementation backlog; runtime changes are not implemented by this document. Tasks and ownership are in [the rendering improvement checklist](../rendering_improvement_todos.md#sprite-streaming-follow-up-2026-10-25).

## Findings and confidence

The reported regression is plausible, but lazy network loading alone is not established as its cause. Fetching and `image.decode()` are asynchronous browser operations; synchronous JS image processing, canvas raster work, first-use uploads, terrain cache misses and background work competing with gameplay are distinct costs. No hardware-GPU browser trace was captured here. Rankings below express expected impact from source inspection, not measured milliseconds or attribution of the reported regression.

### Integrated map sprite sheets

`src/ui/spriteSheetRegistry.js` discovers bundled `dtv*` image/metadata pairs at build time and automatically enables them unless opted out. The eager glob imports URLs, not decoded pixels. Adding sheets expands preparation and decoration candidates for existing players.

`TextureManager.setIntegratedSpriteSheetConfig()` in `src/rendering/textureManager.js` awaits each sheet serially, then synchronously builds tag/group catalogs and decoration cutouts. `loadIntegratedSpriteSheetImage()` caches full source images by path. `buildIntegratedTagBuckets()` and `buildGroupedTagCatalog()` call `getImageTextureWithBlendMode()` inside tile loops. On its first miss, that function calls `buildBlackTransparentTexture()` in `spriteSheetAnimation.js`: full-sheet canvas draw/readback, seed masks, flood fill, alpha processing, then `putImageData`. Later hits still compute `innerCutsSignature()` by enumerating metadata for every tile reference. With T tile references and M metadata tiles, this lookup work can approach O(T×M) per configuration build.

`src/rendering/blackKeyPixels.js` allocates seeds, coverage, reached and flood queue arrays. `src/rendering/decorationCutout.js` additionally composes each group at 64 pixels/cell, reads pixels, samples/sorts border colors, flood-fills and feathers every pixel. These are synchronous main-thread operations. Native-alpha groups skip cutouts. They normally run during configuration/preparation, **not every scroll frame**; correlate settings/startup timing with the observed hitch before blaming steady scrolling on them.

`TextureManager.getDecorationLayout()` can build a whole-map layout on a cache miss and calls `prepareCityBuildings()`. `publishPreparedRuntimeMap()` in `src/rendering.js` already warms it, so normal startup is partly protected. Render lookups still call this method and can rebuild after invalidation. City building preparation affects game state: moving all of this into a rendering worker without an authoritative simulation-side apply step would be incorrect.

`MapRenderer.drawGroundDetail()` and `drawIntegratedLandOverlay()` feed static chunk baking. `drawIntegratedTileImage()` crops and scales source cells to `TILE_SIZE` (32 logical pixels), including rotations. Chunk prewarming is explicitly limited to small maps (at most 24 chunks); first traversal of larger maps and evicted chunks can still trigger work. Faster sprite decoding cannot eliminate that raster cost. A changed sheet handle alone cannot sharpen already baked chunk pixels.

### Prepared units/buildings and background rotation

`scripts/build-prepared-sprites.mjs` already produces densities 1, 2 and 3 for a manually maintained unit/building inventory. It does **not** process integrated map sheet pairs or custom uploaded sheets. `npm run make:prepared-sprites` is separate from `npm run build`; Netlify's build command does not call it. The existing generator uses q95 for unit sprites and q85 elsewhere; preserve existing assets here, and use WebP q85 for new generated assets under repository policy. Visual validation must assess new encodings.

`prepareRuntimeSprites()` in `prepared/renderingPipeline.js` rounds density upward and clamps it to 1–3. `prepareSpriteRegistry()` in `preparedSpritePipeline.js` defers non-building entries except initially present unit types. It requests one selected density, with no low-to-high upgrade lifecycle. Apache has 240 angle/tilt entries referencing a shared atlas: `createSizedBitmap()` crops each into a separate bitmap even at exact density.

After the loading screen is hidden, `gameOrchestrator.js` calls `preloadRemainingPreparedSprites()`. Priorities only reorder entries; **all deferred entries are enqueued**, including Apache states. `createIdleAssetQueue()` in `src/utils/idleAssetQueue.js` deduplicates jobs and limits concurrency to two. Its idle callback ignores `IdleDeadline.timeRemaining()` and `didTimeout`; a timer fallback runs after 16 ms. Async continuations are not constrained to the idle window. There is no scroll signal, demand cancellation, queue byte reservation or eviction. `OffscreenCanvas` constructed on the main thread still executes there.

After deferred preparation completes, `prepareAndPublishSprites()` starts `tankRotationCache.js`. It creates 4 variants × 3 parts × 64 angles = **768 retained canvases**, with temporary 2× supersampling canvases. It yields after up to 8 ms of work, checked after each indivisible rotation job; a job may exceed that slice. An 8 ms slice consumes 60% of a 13.333 ms frame before simulation, input, composition or other loading work. This is an especially concrete background-work competitor. The current angle quantization is existing behavior; this analysis does not authorize coarser angles or further fidelity reduction.

`prepareSpriteRegistry()` retains source promises for the registry's lifetime through deferred loader closures. Cropped Apache bitmaps coexist with the decoded atlas. Registry accounting covers final handles, not all retained sources, worker buffers, staging or GPU copies. Its up-front budget sums all final entries even in deferred mode, so deferral does not make an oversized manifest admissible. There is no per-entry replacement/eviction interface for progressive tiers.

### Existing worker coverage is narrow

`explosionPreparation.js` serializes one explosion job at a time, creates a bitmap on the main thread, starts a worker per job and terminates it on completion/timeout. `explosionPreparation.worker.js` does simple black keying with OffscreenCanvas and transfers the result. It does **not** support the metadata-aware edge-connected map-sheet algorithm or decoration cutouts. On failure/unsupported capabilities, `prepareSheet()` falls back to synchronous main-thread conversion during preparation. Its separate 64 MiB reservation does not include all temporary buffers; failed preparation does not release every reservation/cache entry. General map sheets do not use this worker.

`withTimeout()` rejects the waiter but does not cancel its underlying operation. A late `createImageBitmap()` result can need explicit closing after timeout. Aborted/disposed deferred jobs also need checks at publication and disposal of unpublished results; checking generations only when a job starts is insufficient.

### Network/offline behavior

`src/pwa/sw.js` uses NetworkFirst for map-data paths with a four-second network timeout and offline fallback. `offlineAssetPlan.js` classifies sheet files as bulk offline assets with downloader concurrency five, while prepared image variants are excluded. The `game-playable` event starts deferred offline work near sprite background preparation. These are potential network/storage competitors, not proof of main-thread pixel blocking. New tiers must not silently multiply automatic offline downloads, create stale manifest/image pairs or make offline correctness worse.

## Static memory inventory

Reproduce without rendering: use Pillow `Image.open(path).size` for `debris_craters_tracks.webp` and sorted `dtv*_*.webp` pairs in `public/images/map/sprite_sheets`; sum width×height×4. Read each prepared manifest variant's `decodedBytes`. Rotation estimate is 64×4×cellSize² per tank part, where cellSize is the even-rounded `ceil(hypot(backingWidth, backingHeight))+2` from `getRotatedCellSize()`.

| Inventory | RGBA estimate | Interpretation |
|---|---:|---|
| Ten default sheet images, 2,818,048 pixels | 10.75 MiB | One decoded copy; excludes crystals/explosions, metadata, group cutouts and caches |
| Source plus keyed copies for nine black-mode sheets; alpha detail sheet once | 20.94 MiB | Ground-detail alpha sheet is 0.5625 MiB and needs no keyed copy; browser allocation differs |
| Prepared 306 entries at density 1 / 2 / 3 | 2.23 / 8.89 / 20.02 MiB | Final handles only; 918 density variants total, not all resident simultaneously |
| Tank 768 rotation frames at density 1 / 2 / 3 | 2.81 / 10.31 / 22.77 MiB | Retained pixel storage estimate; excludes canvas/native overhead and temporary supersampling |
| Apache density-3 source atlas | 8.44 MiB | 48×5×96×96×4; approximately another 8.44 MiB in 240 cropped frames |

For a black sheet with P pixels, source canvas + decoded source + ImageData + seed + reached + flood queue can reach roughly **18P bytes** concurrently, excluding browser/GPU copies. The coverage mask used during seed construction adds P at that phase and may overlap until collection. A 1024² sheet therefore has approximately 18 MiB of live processing surfaces/arrays at that stage despite a much smaller compressed file. These are allocation estimates, not measured RSS or GC peaks.

Halving both dimensions reduces decoded area to 25%; retaining full, half and quarter tiers costs 1 + 1/4 + 1/16 = 1.3125 times full-resolution pixel storage before copies. Load tiers selectively and retire superseded tiers. Smaller WebP transfer bytes alone do not establish smaller total native residency.

## Target architecture and tradeoffs

1. Build bundled sheet derivatives, masks, group cutouts and resolution tiers before deployment. Discover image/JSON pairs automatically; fail a stale/missing derivative check. Derivative identity includes source bytes, metadata, key thresholds, groups/inner cuts, algorithm version, footprint and density. Keep placement metadata independent of visual resolution so selected sprites, collision and deterministic map generation do not change with loading order.
2. Freeze an immutable job/result contract with asset/map/density generations and tier. A persistent, bounded worker pool fetches/decodes/prepares dynamic/custom art and transfers ImageBitmaps. The main thread owns publication; worker results never mutate simulation state. Validate dimensions before reserving decoded bytes, cap concurrency and staging, close stale/late results, and terminate/cancel jobs at lifecycle boundaries. Capability detection and worker/CSP/error paths are mandatory.
3. During fast scrolling prioritize visible missing coarse art, then a small directional lookahead. Pause optional refinements and rotation work. Use camera velocity and a settled dwell window with hysteresis, not total time since page load. While stationary, upgrade visible art toward the selected final DPR under time/byte/upload budgets. Never downgrade an already sharp resident region just because the camera moves; memory pressure uses an explicit eviction policy.
4. The latest user request explicitly permits **temporary coarse visual art during fast scrolling**. This is a scoped departure from the earlier fixed-quality preparation checklist. It does not authorize slower animation, lower canvas DPR, changed simulation/collision, permanent low detail, or counting a coarse-tier run as full-quality acceptance. Generate derivatives at build time; avoid ordinary resizing in gameplay. For unsupported worker/bitmap features, prepare bundled derivatives before readiness; prepare custom art through a controlled loading state or cooperative bounded algorithm, with no hidden synchronous pixel fallback during play.
5. Keep logical rectangles/anchors constant; store per-tier source rectangles, padding/gutters, alpha and actual backing density. Coarse bitmaps still require composition to the unchanged logical footprint: record that explicit progressive-tier sampling in the resizing audit. Do not falsely call a coarse draw native-size. Full-tier steady draws must satisfy the existing preparation contract.
6. Upgrade dependent terrain pages locally using per-sheet/tier revisions or a separate retained decoration layer. A global signature change per bitmap completion would cause a rebuild storm. Use bounded staging and frame-boundary swaps, preserving old complete pages until replacements exist, with halo/seam handling and continuously animated procedural water. Avoid making every sprite completion rebuild decoration layout or city state.
7. Worker preparation does not move the current renderer off-thread or guarantee that first drawing/uploading a transferred bitmap is free. Track upload cost separately. Evaluate worker static-page composition before a full OffscreenCanvas renderer migration, which would require serializable render snapshots, ordering, input/display resize handling, water/backend integration and context recovery. GPU work can still compete across contexts.
8. Start with native browser decoding and worker JavaScript. WASM/SIMD is a conditional experiment for remaining measured pixel/packing kernels; running WASM on the main thread still blocks it. Account for module startup, linear-memory copies/peaks, browser support and build dependencies. Shared-memory threading needs cross-origin isolation and an audit of embedded/third-party content. A WASM renderer is not a necessary dependency for streaming.

## Evidence and acceptance protocol

No `/dev/dri` device is exposed in this environment and no hardware GPU was verified. Per AGENTS.md, no GPU/performance benchmark was run. Physical ≥75 Hz GPU certification remains pending. Static dimensions/manifest inspection is not a rendering benchmark.

Capture serially on qualifying hardware: cold fresh boot and first route while deferred loading runs; warm repeated laps; abrupt reversals/jumps; dwell-to-full-detail; mixed/single biomes with default sheets and sheets disabled; selected layered units firing/moving, effects and procedural water; DPR 1/2/3; map/settings/load/context changes; worker disabled/crash and failed assets. Use identical seeds/entity counts/settings and build for comparisons. Sheet-disabled runs are diagnostic attribution, not final acceptance with missing features.

Report independent FPS, p95/p99/max frame time, misses against 13.333 ms, main-thread self time, long tasks (50 ms entries alone miss many deadline failures), decode/processing time by job/tier, queue age/cancellations, first-visible coarse/full latency, bitmap publication/upload/raster timing, cache-hit/miss rates and native memory estimates/GC evidence. Correlate traces with job completions and chunk rebuilds. Verify eventual full detail under sustained load, no starvation, deterministic placement and visual parity at final tier. Compare coarse behavior separately; full-quality Q30/Q31 remain required. Test cancellation, stale completion, timeout, backpressure, eviction pins, failure retries and tier seams with deterministic tests; do not turn software browser FPS into performance acceptance.
