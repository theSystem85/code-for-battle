# Device graphics tuner

The Graphics tab and Performance benchmark selector open a tuner for a 60 FPS target. It runs a separate coastal battle using the game simulator and renderer. The current match resumes after completion, cancellation, or failure. Connected multiplayer matches are excluded so pausing the local renderer cannot stall the shared simulation.

## Workload

- The opening view includes a powered coastal base with every building type, plus every playable unit type. Land units stage on open roads, aircraft start airborne, and ships have water clearance for their full hull. A separate opposing force engages the base from the land, air, and sea.
- The same seeded start is rebuilt for each sample. The benchmark fits the whole base to the display, measures a stationary battle and then traverses the map repeatedly. Preparation and warm-up happen before timing. The report separates the first camera traversal from repeats.
- Compare unit shadows, detailed selection HUD, custom map sprites, rendered smoke, Ocean Surface Water, and Coastal Shallows on and off. Compare 1×, 2×, and 3× backing-pixel density for both game canvases. Only one setting changes in each comparison. The reference starts with effects enabled at the highest tested density up to the native DPR. Run the matrix twice in reverse order to reduce warm-up and thermal bias.
- The detailed HUD switch keeps a basic selection outline and health indication. The smoke switch hides rendered particles while the simulator continues to produce them, keeping combat and random draws comparable. Custom sprite measurements use the active sheets when available, otherwise the bundled default sheets.

## Recommendation and history

The report ranks features by measured p95 frame-time savings and uses CPU update plus render submission p95 to distinguish options when callbacks are display-capped. It shows the FPS and p95 of each tested variant. Candidate selection tests combined reductions in ranked order when individual measurements miss the goal. The reference and measured settings that preserve more detail are preferred when they meet the target. If none meet it, the report returns the fastest verified option within the native density ceiling.

The browser estimates the display's idle callback cadence. The report retains frame count, average FPS, p95, p99, maximum, intervals over 16.67 ms, estimated missed refresh intervals, CPU update and renderer submission time, and GPU timing and JS heap peaks when available. Browser callbacks estimate delivery and do not certify physical presentation or explain garbage collection events. The recommendation requires at least 59.5 measured FPS in the base and scroll phases, p95 callback intervals within 1 ms of the 16.67 ms budget, no estimated refresh misses, and p95 CPU frame work at or below 16.67 ms. A callback later than the 60 FPS frame budget plus half the observed refresh interval is treated as a missed refresh. This keeps ordinary callback timing variation from triggering quality reductions.

Apply reconfigures the running renderer and persists the chosen options. Pixel-density changes prepare resources before resuming. Switching custom sprite mode from the report rebuilds map graphics and occupancy while preserving the current terrain layout. A report is stored in the browser's IndexedDB when the complete run succeeds, replacing the previous report. Each measured control shows a cost tooltip from the ⓘ button immediately after its label. Hover, keyboard focus, or tap opens the tip. The benchmark report opens over Graphics settings and returns focus there when closed. Reports and settings stay on the device.

## Validation

Use `npm run test:unit` for the profile matrix, measured recommendation logic, and coastal placement rules. For the complete workflow, run `npm run dev -- --host 127.0.0.1 --port 5192 --strictPort` and open `http://127.0.0.1:5192/?tutorial=0&size=60&seed=11` in a foreground browser with a verified hardware adapter. Choose **Graphics → Tune graphics for 60 FPS**, inspect the ranked variants, apply the proposal, reload, open the last report, and check a per-setting tooltip. Also cancel a run and confirm that the prior report and current map still exist. Physical 60 FPS acceptance requires compositor or display measurements on qualifying hardware.

The smoke check runs once per rendered frame. The detailed HUD check runs once per visible unit overlay, plus mode reads at selection draw sites. At 200 visible units and 60 FPS that is 12,000 overlay checks per second. At 3× DPR existing raster areas consume nine times the backing pixels of 1× DPR. These checks add no draw calls, canvas fills, per-unit allocations, or entity searches. The tuner creates its fixture only between passes and uses the existing prepared sprite and terrain pipelines.

On 2026-11-19, headed Chrome verified Apple M1 Metal hardware, WebGPU terrain, and about 60 Hz idle callback cadence. The full 16-pass run recommended 2× with all effects enabled. The prepared, fit-to-view sample rendered into 1479×1286 pixels at 1.005 effective world DPR. For this measurement the 698 callbacks averaged 60.00 FPS, with p95 17.6 ms, p99 18.5 ms, a maximum of 18.7 ms, and 412 intervals over 16.67 ms. The first scroll averaged 60.00 FPS with p95 18.5 ms. Repeated scrolling averaged 60.00 FPS with p95 17.6 ms. Mean CPU update and render submission took 1.22 ms and 3.10 ms respectively. The largest sampled GPU time was 1.51 ms and peak sampled JS heap was 150.0 MiB. The battle reached 10 projectiles and 300 smoke particles. These callback observations leave physical presentation acceptance and GC attribution pending.

The browser run verified Apply, refresh persistence, the per-setting tooltip, reopening the saved report, and cancellation while preserving the active match and last report. Lint passed. The full unit suite passed 5,917 tests and reproduced the existing woodland atlas alpha mismatch in U05433.

The follow-up hardware run completed 18 passes across nine profiles on Apple M1 WebGPU. The reference averaged 59.99 callback FPS with 5.30 ms p95 CPU frame work. Coastal Shallows off averaged 60.00 FPS with 4.20 ms p95 CPU frame work. Ocean Surface Water off averaged 60.00 FPS with 4.80 ms p95 CPU frame work. Each water pass held the other setting on. The local UI check reopened this saved report over Graphics, verified desktop hover and click and mobile tap, and closed the report back to the same tab.
