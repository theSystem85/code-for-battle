## User documentation

Update `Documentation.md`, README feature summary and appropriate automation feature docs to explain why the game is called Code for Battle: players author automation, choose what to control/build, and let state machines issue normal game commands. Preserve existing guide coverage. Link the dedicated [CFBL language reference](../docs/cfbl-language-reference.md) and a tutorial rather than burying the whole grammar in the landing page.

The language reference must contain the entire structural EBNF and closed terminal catalogs from spec 100, category/capability tables, numeric bounds/defaults/modes/units, operator precedence/depth, IF/ELSE pairing and priority, WHILE hold/UNTIL return, AFTER simulation-time cancellation, one-time/continuous behavior, state generation/reordering and examples for all four categories. Generate catalog tables/example validation from shared language metadata when practical; handwritten docs must be checked for drift. Clearly identify unsupported conditions/types and current production-vs-control capability differences. Never describe every producible unit as controllable.

Tutorial requirements:

1. Create a unit automation in Buttons with autogenerated states; choose type/scope/run mode, a condition, target/action, then save/enable/apply.
2. Switch to CFBL and explain source of truth, searching a legal slot, fuzzy choice selection, number entry, copy/paste, undo and switching back without losing data.
3. Use an IF/ELSE pair and explain why an early pair preempts later rules. Show a WHILE example for sustained control and an AFTER example for stable delayed conditions.
4. Build units with quantity/delivery and build a building with affordability/tech/queue/placement requirements. Explain independent opt-ins, failure/retry status and the one-pass unit-loss event.
5. Apply to a defence building, show capability-sensitive options, manual priority/hold-fire conflicts, and state-machine inspection.
6. Show phone full-screen use with keyboard/flyout controls; explain that tablets retain a bounded dialog.

Include troubleshooting for unavailable measurements (including NOT), pending queries versus source, invalid paste, migration repair/version conflicts, target disappearance, direct-order gates and self-transition cycles. Explain compiled execution in one technical sentence in the developer docs; player flows should focus on behavior, not opcodes or persistence keys.
