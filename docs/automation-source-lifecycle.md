# Automation source and session integration

CFBL version 1 is authoritative. `cfb-automations-v2` stores `recordVersion: 2` records with source, metadata, document revision, behavior revision and the validated invisible identity map. Machine projections are immutable derived data. Compilation runs during save/import/load; `getCompiledPolicyProgram(id)` returns the prepared artifact. Neither artifacts nor JSON projections are persisted as authoritative behavior.

`createAutomationDraft(actorId, policyOrId)` in `src/automation/automationDraft.js` creates one private draft. `getSnapshot()` and immediate `subscribe(listener)` expose `source`, `policy`, `astProjection`, `identityMap`, `baseRevision`, `draftRevision`, `viewPreference`, diagnostics and undo availability. `transact(callback)` accepts a DAV machine operation; `setSource(source)` accepts an ATV legal source operation. Both validate and print source atomically. Rejected edits do not replace accepted source. `setView`, `undo`, `redo`, `save` and `cancel` share the same accepted history. The modal owns pause/focus/query staging and cancels the controller when closing. The local view preference never enters simulation state.

Document `revision` detects stale saves, including metadata-only changes. `behaviorRevision` advances only for behavior changes. A rename or canonical no-op retains compiled artifact/runtime identity. Changed behavior resets only registered affected bindings and clears their old defence intent; independent manual orders survive. Register entities when attaching global bindings too. Text insertion/removal/reordering reconciles unchanged constructs, ignoring source offsets, while DAV carries existing invisible IDs.

Legacy `cfb-unit-policies-v1` is never overwritten or removed. Valid records migrate independently; malformed records are quarantined with exact data and an explanation. Repeated load reads the new store once. Quota failures retain usable in-memory records and the untouched legacy backup. `getAutomationRecovery()` exposes errors; `exportAutomationRecovery()` includes current source, recovery entries and both stored backups.

`exportAutomationSession(entities)` exports records, enablement, both category opt-ins, order/owner sequences, typed entity bindings, runtime progression and final defence intents. `restoreAutomationSession` validates source/identities/references and rebuilds artifacts before runtime restoration. Unit/building IDs are typed and owner checked. Runtime-only network snapshots reuse the existing record/artifact and do not bump the store version or reparse source. Routine host snapshots include source only on source/store changes; new connections and explicit lockstep resync include all sources.

Register production continuation with `registerAutomationRuntimeProvider(id, { export, restore })`. Save restore invokes the provider; routine `authority: 'host-snapshot'` never overwrites a client's own producer. Existing owner-local production emits ordinary production/spawn commands once, while control execution remains host authoritative. The source record itself grants neither enablement nor production opt-in.

`subscribeAutomationMutations` supplies validated owner inputs, which `gameCommandSync.js` records for replay and sends through existing game-command transport as `automation-edit`. Host receipt validates owner/source version before applying and relaying. `applyAutomationMutation` suppresses duplicate owner sequences, validates typed entity ownership and installs the agreed behavior revision. Replay dispatch applies recorded source inputs; live authoring is locked, and runtime engines must skip replay execution so recorded effect commands remain authoritative. Prepared behavior hashes include accepted source/revisions and enablement/opt-ins, excluding editor state and display names.

Focused acceptance: `npm exec vitest run tests/unit/automationSource.test.js` covers migrations/recovery, cross-view transactions, undo, stale metadata and behavior conflicts, structural identities, runtime preservation/reset, typed collisions, mid-delay/hold continuation and routine-snapshot artifact/producer isolation. Full integrated unit/integration/browser checks belong to the orchestrator release pass.
