# Unit automations: condition catalog, unit command API and activity display

- [x] **Unit automation conditions, command API and activity display**: Automations get the long condition list (`==, <=, >=, <, >`, `not`/`and`/`or` nesting; internal, external and sensing conditions that the game really has), a unit command API that refuses disallowed commands, per-automation "enabled" and "in control" counts, a HUD badge for actively controlled units, and per-unit automation status in the unit detail panel. Voice vibe coding, hotkey scripts, one-click attack plans, base-build scripts, a shared command path and migrating existing human/enemy behavior onto the API are spec only. Two conditions are skipped because the game has no such data (crew per role, hit history). Spec: [Unit automation — conditions, command API and activity display](../../specs/unit-automation-conditions-and-command-api.md)
