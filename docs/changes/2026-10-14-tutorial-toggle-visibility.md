- [x] **Bug: recurring tutorial dock visibility and portrait overlap**
  Centralize tutorial visibility and honor hidden state; anchor the portrait dock at the top-left, clear of the condensed sidebar.
  Spec: [Tutorial system](../../specs/021-tutorial-system.md)

Archaeology: searched TODO/Bugs.md, TODO/Improvements.md, docs/changes/, prompt-history/, `git log --all -i --grep=tutorial`, and `git log --all -S 'tutorial-dock--hidden'` / `-S 'body.mobile-portrait .tutorial-dock'`. The supplied PR list identifies #372/#374/#373 as unmerged and #386 as unmerged; these cannot be treated as shipped fixes. #376 (2ce9f618) introduced the portrait dock's bottom-right rule. #387 (5f48ca5f) repeatedly patched completion/reload/startup with a visibility class. #432 (0d2d7493) split UI creation into a module, retaining duplicate visibility decisions. #440/#441 (121a5684/5deeee4d) anchored the expanded card, not the dock. #479 (6cf3c8ce) fixed cursor visibility separately. #468/#678/#712 provide mobile-layout context; #712 was reported open. GitHub was not accessed.

Root cause: the later `.tutorial-dock { display: flex }` author rule defeats the browser's default `[hidden]` display rule. Only some paths added `tutorial-dock--hidden`; Skip/Stop and overlay-visible state relied on `hidden` alone. Independent animation-end callbacks also wrote visibility after state transitions. The dock retained bottom-right portrait positioning, even when the card moved top-left. No evidence showed layout recreating the dock or localStorage being the current settings authority: tutorial settings use the shared IndexedDB storage adapter (legacy localStorage is migration input).

Fix: `syncVisibility()` alone derives dock and overlay visibility from active/enabled/completed/minimized/invite state. Creation/reuse, settings changes, start/stop, completion, minimize/restore and layout updates route through it. Explicit CSS respects `[hidden]`; remove the legacy class and asynchronous visibility writers. Manual start after completion resets progress consistently. Completion stops immediately without a delayed callback that could stop a restarted tutorial. Portrait dock uses top/left safe-area offsets. Tutorial icon controls use accessible labels and custom CSS tooltips, with no title attributes or new scrollers.

Coverage: permanent `tests/e2e/tutorialToggleVisibility.test.js` uses the existing Playwright config and iPhone 13 emulation. It exercises minimize/restore, Skip, Settings, final Skip step completion, persisted-state reload, layout/late-animation events, and visible bounding-box nonintersection with the condensed sidebar. Unit coverage verifies stop and the shared visibility state. Changes run on UI events only, not simulation/render hot paths; no per-entity work or canvas rendering changes.
