# PR #688 round 3 (2026-10-17, 0.61.0)

Rebased onto main 0.60.0; this PR now ships as 0.61.0 (`features/0.61.0.json`).

- **City HP tenfold lower.** `CITY_BUILDING_HEALTH` is now 150 / 250 / 400 HP for 1 / 2 / 4 tile footprints (was 1500 / 2500 / 4000); other footprints use 100 HP per tile.
- **Normal attack on cities.** `findEnemyTarget` falls back to a living city under the cursor, and `updateEnemyHover` shows the attack cursor over it, so a standard click attacks without force attack. Cities are still not in `gameState.buildings`, so auto-targeting ignores them. Host commands, lockstep, replays and save restore resolve city ids through `findCityBuildingById`.
- **City houses sit on streets.** City clusters reserve one-tile streets on the three-tile block grid, keep them around placed buildings and connect each street component to the existing road network. The streets are stamped as normal `street` tiles (flag `cityStreet`), so they render and path like other roads, and buildings never cover them. Verified in the browser: seed 23, 96x96, 30 city buildings, all 30 touching a street, 239 city street tiles, connected to the main road network (`/workspace/vfx-verify/688-r3/3-city-streets.png`).
- **Decals only on passable tiles.** `setTileDecal` refuses `impact`/`crater` decals on water, rock, seed crystals, blocking buildings, living city buildings and impassable decorations (named blockers registered by `cityBuildings.js` and the renderer). `drawTileDecalOverlay` applies the same check, so older marks stay hidden under structures. `debris` is exempt because it is the rubble of the destroyed structure. Browser check: 16 impact/crater requests around and on a 2x2 city block created 12 decals around it and none on it (`/workspace/vfx-verify/688-r3/4-no-decal-on-building.png`).
- **Sprite isolation keeps interior pixels.** SSE click isolation and auto detection copy everything the silhouette encloses; only background touching the bounding-box edge becomes transparent (`copyComponentWithInterior`). The runtime black key on metadata sheets is now edge-connected (`buildBlackKeySeedMask` + `applyEdgeConnectedBlackKey`), and decoration cutouts flood only border-connected ground. Enclosed holes are now opaque; a sprite that needs a see-through hole must carry real alpha. Tests: `tests/unit/spriteInteriorPixels.test.js`; screenshot comparing the old global key with the new paths: `/workspace/vfx-verify/688-r3/5-isolated-sprite-interior.png`.
- **Map settings Apply button.** Sidebar map-setting edits no longer regenerate the map on change. `Apply map settings` is disabled until a watched value differs from the last applied snapshot (reverting disables it again) and regenerates once on click. Player count (multiplayer section), ore spread interval and SSE-driven regeneration are unchanged. Spec: [136](../../specs/136-map-settings-apply-button.md). Browser check: editing water % and seed left the map untouched (0 regenerations) and enabled the button; clicking it regenerated once with seed 77 / water 20 and disabled it (`6a-apply-disabled.png`, `6b-apply-enabled.png`).
- **Strict snow placement.** Cause found in the browser: the green shrubs/logs on snow were the organic-terrain fallback details (`terrain-details.png` row 192, summer vegetation) drawn on any land tile without a sheet decoration. `OrganicTerrain.drawDecoration` now skips snow tiles. The layout pools are strict too: on snow, a group tagged as vegetation (`trees`, `shrubs`, `bushes`, `vegetation`, `plants`, `flowers`, `reeds`, `farm`, ...) is only used when it carries an explicit `snow` tag (`groupAllowedOnBiome`); universal rocks, ruins, landmarks and city props are still allowed. `availableFutureSheets` now auto-registers any bundled `dtv<N>_<name>` webp+json pair beyond the required dtv3 sheets, so a snow-tagged winter sheet only needs its files. Screenshots: `7-snow-before.png`, `7-snow-no-green-vegetation.png`.
- **Winter vegetation sheet `dtv3_winter`.** 30 sprites from Patrick's approved sources (`winter_bare_trees`, `winter_pines`, `winter_shrubs`, `winter_small`, 1408x1408 on black) isolated and packed with the SSE browser API (`newSheet` 6x8 @ 64 px, `extractAll` cutoff 16 / minArea 200 / gap 1, center anchor, `compact`, `exportSheet({ lossless: true })`), so interior dark pixels are kept per the isolation fix. Scale is about 10 m per tile: 6 bare trees 2x2 (ratio 0.29), 6 pines 1x1 (0.122), 9 snowy shrubs 1x1 (0.13), 9 tufts/reeds/snow mounds 1x1 (0.1). Tags are only `decorative`, `snow`, `impassable` (trees, pines) or `passable` (shrubs, tufts, reeds), plus `group_N` on the 2x2 trees. The SSE export was re-encoded losslessly (pixel-identical, 786 KB to 142 KB). Registered automatically as an optional sheet via the `dtv<N>_*` discovery; off by default, never in `index.json`. Browser check on a 96x96 snow map with the sheet enabled: 201 winter cells placed, 0 non-snow vegetation cells on snow (`/workspace/vfx-verify/688-r3/winter.png`).
